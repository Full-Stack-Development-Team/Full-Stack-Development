 Database Schema Documentation

This document describes the database architecture and data models used by the backend application.

---

 1. Database Overview

The application uses:

- MongoDB
- Mongoose ODM

MongoDB is a NoSQL document database. Data is stored as documents inside collections.

The application currently contains two main entities:

1. User
2. Task

---

 2. Database Collections

The database contains the following main collections:

```text
users
tasks
```

 Users Collection

Stores registered user information.

 Tasks Collection

Stores tasks created by users.

---

 3. Entity Relationship Overview

The main relationship is:

```text
USER 1 ─────────────── N TASK
```

One user can have many tasks.

Each task belongs to one user.

---

 5. Relationship

 User → Task

Relationship:

```text
One-to-Many (1:N)
```

Explanation:

- One user can create multiple tasks.
- Each task stores the ID of its owner in the `user` field.
- The `user` field is an ObjectId reference to the User document.

Example:

```text
User
  |
  ├── Task 1
  ├── Task 2
  └── Task 3
```

 6. User Schema

The User model represents application users.

 User Fields

| Field | Data Type | Description |
|---|---|---|
| `_id` | ObjectId | Unique identifier generated by MongoDB |
| `username` | String | Username of the user |

 10. Foreign Key / Reference

MongoDB does not use traditional relational foreign keys in the same way as SQL databases.

Instead, the Task document stores a reference to the User document.

```text
Task.user → User._id
```

Example:

```json
{
  "_id": "TASK_ID",
  "title": "Complete Documentation",
  "description": "Finish API documentation",
  "status": "Todo",
  "user": "USER_ID"
}
```

The value of:

```text
user
```

identifies the owner of the task.

 22. Database Security

The application uses authentication to protect task-related operations.

JWT authentication is used to identify authenticated users.

Important security considerations include:

- Passwords should not be stored as plain text.
- JWT secrets should be stored in environment variables.
- MongoDB credentials should be stored in `.env`.
- `.env` should not be committed to GitHub.
- Protected endpoints should require valid authentication.

---

 23. Environment Configuration

The database connection is configured using environment variables.

Example:

```env
MONGO_URI=your_mongodb_connection_string
JWT_SECRET=your_jwt_secret
PORT=5000
```

Actual credentials must not be included in documentation or committed to the repository.

--- 25. Summary

The database architecture is based on two main entities:

```text
USER
  │
  │ 1:N
  ▼
TASK
```

 User

Stores:

- User ID
- Username
- Email
- Password

 Task

Stores:

- Task ID
- Title
- Description
- Status
- User reference

The `Task.user` field creates the relationship between a task and its owner.

This architecture supports the application's authentication and task-management requirements.
